        Works even if you don't fill anything in

        Every document section has a short hint and a fictional example in a <!-- FILL --> comment. Fill in what you know, or nothing at all: the first command, /sdlc-init, reads your code, fills in what it can work out (marked as inferred, so you can check it) and asks you only about what it can't, such as the product's purpose or who uses it. Claude never treats the examples as facts.

        Accurate by design

        • Evidence, not claims: /implement and /fix-bug must run the tests and show the results; reviews point to file and line.
        • Sources for research: the researcher ranks sources (official docs for your versions first), only cites pages it actually opened, and gives a confidence level.
        • Testable requirements: acceptance criteria written as Given / When / Then turn directly into test cases, linked in a traceability matrix.
        • Checked before download: every generated file is validated against Claude Code's formats and limits.

        Project ZIP, workspace or plugin?

        The project ZIP goes into one repository and is committed, so the whole team shares the same setup. The workspace ZIP is for microservices: clone all your services into one folder, unzip the kit at its root and open Claude Code there. One setup covers every service, each service gets its own doc, and a clone script lets teammates fetch all the services at once. The plugin is installed once and gives you the commands in every project, used as /sdlc-kit:research; its /sdlc-kit:setup command copies the project files (instructions, rules, settings and docs) into each project without overwriting yours.

        Privacy

        When you pick a folder, your browser reads the folder names and your build files (to detect the stack) locally. Only your answers and the folder names are sent to generate the kit. File contents never leave your computer, and nothing is stored.

        Frequently asked questions

        What is CLAUDE.md?

        A Markdown file Claude Code loads at the start of every session in your project. It holds the instructions Claude should always follow: build commands, conventions and how the project is organised. Keep it short; detailed knowledge belongs in docs that Claude reads when needed.

        What are Claude Code skills and subagents?

        Skills are instructions saved as SKILL.md files that become slash commands, such as /test-cases. Subagents are specialists with their own instructions and tools that Claude can hand a task to, such as a code reviewer. This generator creates both, plus the rules and docs they rely on.

        Does it work for any language or framework?

        Yes. The commands are language-neutral and work out your build and test setup from the project. Optional rules add specific guidance for Spring Boot, React, Node.js APIs and 18 test frameworks including JUnit, TestNG, Selenium, Playwright, Cypress, Jest, Vitest, pytest, xUnit, NUnit, Go, RSpec, PHPUnit and k6.

        Will it overwrite my existing CLAUDE.md?

        No. Tick the option and the kit’s instructions go into CLAUDE.sdlc.md, with one line to add to your own file. The plugin’s setup command never overwrites existing files without asking.

        Can I use it for microservices?

        Yes. Choose the workspace format, or tick “This folder holds several services” and pick the folder that holds them. The kit goes in that parent folder instead of in every service, lists your services with their stack and git URL, writes a doc per service and adds a script that clones any missing services. Always open Claude Code at that parent folder.

        Can I change the generated files?

        Yes. Edit any file in the preview before downloading, or edit them later in your project. They are plain Markdown and JSON.

        Is it free?

        Yes. No sign-up is needed.
