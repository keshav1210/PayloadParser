# k6 (load and performance tests)

- **Permission first**: never run load tests against production or shared environments without explicit
  approval and a time window. Default to a dedicated test environment.
- **Run**: `k6 run load-tests/checkout.js`; override with `--vus 20 --duration 2m`, or `-e BASE_URL=…` read
  as `__ENV.BASE_URL`.
- **Shape**: in `export const options`, use `stages` for ramp-up, steady load and ramp-down, or `scenarios`
  for several user types. Start small (smoke test with 1-2 virtual users) before a full load test.
- **Pass/fail**: define `thresholds` from the quality requirements, e.g.
  `http_req_duration: ['p(95)<500']`, `http_req_failed: ['rate<0.01']`. A run without thresholds proves nothing.
- **Checks**: `check(res, { 'status is 200': (r) => r.status === 200 })` on important responses; checks
  don't fail the run by themselves, thresholds do.
- **Realism**: think time with `sleep(1)` between user steps (here a pause is intended), varied test data,
  and correlation of tokens and IDs between requests.
- **Report**: p50/p95/p99 latency, throughput, error rate, and where the limits were reached.
